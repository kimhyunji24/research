# 프롬프트 강건성 점검 계획: ReAct 원 예시 (2026-10-17, 데이터를 만들기 전에 기록)

## 왜 하는가
지금까지의 모든 결과는 직접 만든 프롬프트 v2(규칙 6줄 + 직접 쓴 예시 1개, valid_unseen을 보며 튜닝) 하나에서 나왔다.
"프롬프트를 바꾸면 결론이 달라진다"는 반론에 답하려고, **외부에서 널리 쓰는 기준 프롬프트**인 ReAct(Yao 등, 2023)의 ALFWorld 예시로 같은 비교를 한 번 더 한다.
- 근거: 프롬프트 형식만 바꿔도 성능과 모델 순위가 크게 바뀐다(Sclar 등 ICLR 2024; Mizrahi 등 TACL 2024). 진실성 프로브는 템플릿이 바뀌면 잘 옮겨 가지 않는다(2604.03754).
  가장 가까운 선행연구(Doomed from the Start, 2607.06503)는 프롬프트 하나만 썼다.
- 범위: **결론 방향이 프롬프트 2개(v2, ReAct)에서 같은지**만 본다. 다중 프롬프트 문헌 기준으로 2개는 최소 수준이다(한계로 기록).
- 기존 결과(v2)는 바꾸지 않는다. 이 점검은 보조 근거다.

## 프롬프트 출처 (고정)
- 저장소 `ysymyth/ReAct`(MIT 라이선스), commit `6bdb3a1fd38b8188fc7ba4102969fe483df8fdc9`, 파일 `prompts/alfworld_3prompts.json`
  (sha256 `a10976b4ae99f4802aa9e621933bb71065ae103f2bd273a24466ab1005fbc45a`). 저장소에 사본과 라이선스를 함께 둔다(`prompts/react/`).
- 원 방식(`alfworld.ipynb`): 과제 유형별로 `react_{유형}_1 + react_{유형}_0` 예시 2개를 고른다(put, clean, heat, cool, examine, puttwo; 게임 경로 접두어로 매핑).
  머리말 `Interact with a household to solve a task. Here are two examples.\n` + 예시 2개 + `\nHere is the task.\n` + 현재 게임의 첫 관찰 + 지금까지의 기록 + `>`.
  원 실험은 text-davinci-002 completion이고, 행동은 `> 행동` 줄, 생각은 `> think: …`이며 환경은 생각에 `OK.`로 답한다.
- 프롬프트 길이(Qwen2.5 토크나이저, 예시 부분만): 1,115~1,571 토큰. v2 프롬프트 전체의 중앙값은 864 토큰이다.

## 원 예시에서 바꾸는 것 (최소 수정, 전부 공개)
| # | 바꾸는 것 | 이유 |
|---|---|---|
| 1 | 행동 `put A in/on B` → `move A to B`, 그 관찰 `You put the A in/on the B.` → `You move the A to the B.` | alfworld 0.4.2의 행동 문법(우리 환경의 admissible 행동에 `put`이 없음, `move A to B`만 있음). 2026-10-08에 v2 예시에서 같은 불일치로 성공이 0에 가까웠던 경험 |
| 2 | 행동 선택: 생성 대신 **후보 점수화**(v2와 같음, `score_norm: sum`, `help`·`inventory`·`look` 제외). 따라서 에이전트는 `think:`를 쓰지 않는다. 예시 속 `think:` 줄은 그대로 둔다 | v2와 같은 정책이어야 프롬프트 효과만 비교된다. ReAct의 think 내용이 성능에 거의 영향을 주지 않는다는 보고(Verma 등 2024, 2405.13966)가 있다 |
| 3 | 후보 점수 접미사: `> ` 다음의 ` {행동}\n`의 로그확률 합(아래 형식 A) | completion 형식에 맞춤 |
| 4 | 현재 게임의 관찰은 환경 출력 그대로 쓴다(예: `You arrive at cabinet 1. The cabinet 1 is closed.`). 예시 속 관찰(도착 문구 없음)은 고치지 않는다 | 원 notebook은 옛 환경의 `You arrive at loc N.`만 지웠다. 문체 차이는 남는다(한계) |
| 5 | 기록은 원 방식대로 **에피소드 전체**를 유지한다(v2는 최근 6 step) | 원 방식 유지. 30 step 상한이라 길이는 감당 가능 |
| 6 | admissible 행동 목록은 프롬프트에 넣지 않는다(원 방식). 후보 점수화가 목록 안에서만 고른다 | 원 방식 유지 |

### 형식 (2026-10-17 사용자 확정: 형식 A)
- **형식 A: chat template 없이 원 completion 텍스트 그대로.** 프롬프트가 `>`로 끝나고 후보 ` {행동}\n`을 점수화한다. hidden은 마지막 `>` 토큰에서 뽑는다. 원 실험에 가장 가깝다.
- 쓰지 않는 형식 B(원 텍스트를 user 메시지 하나로 넣고 `{행동}<|im_end|>` 점수화)는 실행하지 않는다.
- 토크나이저의 BOS 처리 등 형식 A의 세부(특수 토큰 없이 원 텍스트만)는 코드에서 고정하고 회귀 점검 기록에 적는다.

## 데이터
- actor: Qwen2.5-3B-Instruct(`aa8e7253`, bf16), 탐욕, `max_steps: 30`, seed 0. 게임: `results/games_main3b_first250.json`(v2의 탐색 구간과 같은 250게임).
- 메모리: 프롬프트가 v2의 약 2~3배라 `cand_batch: 16`(필요하면 8, 실행 전에 고정해 기록). 예상 GPU 약 1.5~2시간(확인 필요).
- 출력: `data/react_qwen25_3b/`. 수집 직후 점검: 250 episode, steps 행 = hidden 행, NaN·inf 0, ext4 경고 0, sha256 목록 commit, USB 백업.
- 코드: `collect/rollout.py`에 `prompt_style: react`(원 예시 로드·수정 1, 형식 A/B) 추가. 기본값은 v2 그대로이고, 변경 후 v2 회귀 점검(main_3b 처음 5게임 최대 차이 0)을 다시 한다.
- 수집 전 확인: 원 예시 2개가 수정 후 우리 환경에서 그대로 재생되는지(예시의 행동 열을 해당 게임 유형의 임의 게임에 넣는 것이 아니라, 문자열 치환 결과만 점검). 파일럿은 하지 않는다(결과를 보고 프롬프트를 고치지 않기 위해).

## 분석 (결과 보기 전 고정)
- **주 비교**: 과제 단위, 3B 자기 hidden **75% layer linear vs baseline 5단**, step 0, 1, 2. 장면 단위 5-fold 교차적합 2회, nested C, 장면 cluster bootstrap 1,000회, 순열 100회. v2 확증·모델 확장과 같은 코드·설정.
- 판정 규칙: 기존과 같다(우수 = CI 하한 > 0, 비열등 = 하한 > −0.05(사후 마진), 열등 = 상한 < 0, 그 밖은 결론 없음).
- **해석 규칙(결과 보기 전)**
  | 결과 | 해석 |
  |---|---|
  | 우수 0/3이고, v2와 같은 방향(프로브 ≤ baseline 또는 결론 없음) | "외부 기준 프롬프트에서도 프로브가 겉보기 baseline보다 낫다는 증거가 없다" → 프롬프트 강건 |
  | 우수가 하나 이상 | "결론이 프롬프트에 따라 달라질 수 있다"로 보고. v2 결과를 일반화하지 않는다. 시도 단위로 넓힐지는 새 사전 기록으로 정한다 |
  | 성공이 25개 미만 | CI가 넓어 판정이 약하다는 단서를 붙인다(성공 수와 CI 반폭 함께 보고) |
- 보조(판정 대상 아님): 성공률(v2 같은 250게임 대비, 게임 단위 짝지은 비교), baseline 사다리 1~5단, 50% layer.
- 탐색적: v2 데이터로 학습한 프로브를 ReAct 궤적에 적용하는 **전이 점검**(같은 게임, 같은 layer). Qwen3-4B에 같은 점검(시간이 되면, 별도 기록).

## 범위 밖 (한계로 기록)
- 시도 단위(다중 rollout)·시간 한도 100·조기 중단은 ReAct 프롬프트로 하지 않는다.
- 자유 생성(think를 실제로 생성하는 원 ReAct 정책)은 하지 않는다. 우리 결론은 후보 점수화 정책에 대한 것이다.
- 프롬프트 2개뿐이다. 문법·관찰 문체 수정이 있어 "원 프롬프트 그대로"가 아니라 "원 예시를 최소 수정한 것"이다.
