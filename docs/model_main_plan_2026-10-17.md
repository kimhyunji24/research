## 데이터
### 과제 단위 (탐욕)
- 게임: `main_3b`의 처음 250게임(Qwen2.5-3B 탐색 구간과 같은 게임). `--game_list`로 고정(설치 간 게임 순서 문제, `model_pilot_plan` 참고).
  목록 파일 `results/games_main3b_first250.json`(만들어 sha256을 이 문서에 추가). 같은 게임이므로 모델 사이에서 게임별 결과를 짝지어 비교할 수 있다.
- 정책: 각 모델 설정 그대로, `max_steps: 30`(시간 한도 100 판정에서 30 step 라벨이 좋은 대리값, `horizon100_plan` 결과), 탐욕, seed 0.
- 처음 20게임은 파일럿과 같은 게임·같은 설정이라 결정적이면 파일럿과 같다(점검 항목). 파일럿에서 본 것은 성공 수·시간·메모리뿐이다.
- 출력: `data/main_<모델>/` (예: `data/main_qwen3_4b`). 예상 GPU: Qwen3-4B 약 1시간(14.9초/episode).

### 시도 단위 (다중 rollout, T = 1.0 샘플링)
- 게임: 그 모델의 탐욕 250게임 결과로 층화해 성공 25 + 실패 25게임을 `seed=1`로 무작위 추출(`collect/make_game_list.py` 방식).
  성공이 25개 미만이면 성공 전부 + 같은 수의 실패. 성공이 10개 미만이면 시도 단위 분석을 하지 않고 기록만 한다.
- 반복: 게임당 8회, `sample_temperature: 1.0`, `sample_seed: 1`. 50 x 8 = 400 episode. 예상 GPU: Qwen3-4B 약 1.7시간.
- 출력: `data/multi_rollout_<모델>/`, 게임 목록과 메타 `data/multi_rollout_<모델>_games/`(sha256을 기록).

### 수집 직후 점검 (하나라도 실패하면 분석하지 않고 보고)
- episode 수(250, 400), 게임마다 정해진 횟수, steps 행 수 = hidden 행 수, hidden NaN·inf 0, 수집 중 ext4 경고 0.
- 탐욕 처음 20게임이 파일럿과 action·hidden 최대 차이 0.
- sha256 목록을 만들어 `results/sha256_<폴더>.txt`로 commit하고, 데이터는 USB에 sha256 검증과 함께 백업.

## 분석 (결과 보기 전 고정)
모든 분석은 Qwen2.5-3B와 같은 코드·설정(장면 단위 5-fold 교차적합 2회 반복, nested C, 장면 단위 cluster bootstrap 1,000회)이다.

### 과제 단위 주 비교 (모델마다 1개 family)
- 프로브: 그 모델 자신의 hidden(actor = reader), **75% layer**, linear. vs **baseline 5단**. step 0, 1, 2. 순열 100회.
  75% layer는 Qwen2.5-3B 탐색에서 고른 값이다. 새 모델에서는 데이터를 보기 전에 정하므로 사전 지정이다(새 모델에 대해서는 확증과 같은 역할).
- 판정(기존 규칙 그대로): 우수 = 차이의 95% CI 하한 > 0, 비열등 = 하한 > −0.05(마진은 Qwen2.5-3B 탐색 뒤 정한 값), 열등 = 상한 < 0, 그 밖은 결론 없음.
  3개 step에 Holm을 적용한 우수 판정을 함께 보고한다.

### 시도 단위 주 비교
- 게임 내 쌍 AUROC, step 1~3, 프로브(75% layer linear) vs baseline 4단·5단(6개 비교). 게임 단위 bootstrap 1,000회, 게임 안 순열 1,000회.
- 보조 1(동점 제외), 보조 2(시점 맞춘 baseline 4t·5t)를 함께 실행한다(`probes/within_game_supp.py`).
- 해석 규칙은 `docs/multi_rollout_plan_2026-10-15.md` "해석 규칙"을 그대로 쓴다(Holm 6개, 동등은 CI가 ±0.05 안, 0.5 근처 정의).
  Qwen2.5-3B에서 확인한 대로 게임 bootstrap CI가 명목보다 좁을 수 있다는 단서를 붙인다.
- 보조 지표: η²(게임이 설명하는 결과 분산), 난이도 오라클(그 모델의 탐욕 결과) 단독 AUROC와 오라클 대비 증가분.

### 모델 사이 비교 (기술적)
- 주 질문의 "크기·계열에 따라 어떻게 바뀌는가"는 모델별 결과를 나란히 보고하는 것으로 답한다(모델 3~4개라 모델 수준 검정은 하지 않는다).
- 같은 250게임에서 모델별 탐욕 성공을 짝지어(게임 단위) 성공률 차이와 게임 결과 일치도를 기술한다.
- 미리 정한 해석: 모든 모델에서 과제 단위는 baseline과 비슷하고 시도 단위 신호가 약하면 "결론이 Qwen2.5-3B에 특수하지 않다".
  특정 모델에서만 프로브가 우수하면 그 모델의 결과로만 보고하고 일반화하지 않는다.

## 탐색적 (확증 근거로 쓰지 않음)
- 다른 layer(25/50/100%), MLP, 다른 모델의 hidden으로 읽기(reader 교차), 후반 step.

## 필요한 코드 작업 (결과와 무관, 수집 전)
- `results/games_main3b_first250.json` 생성, 모델별 설정(`configs/main_<모델>.yaml`, 파일럿 설정에서 출력 폴더만 다름).
- 다중 rollout 게임 목록·메타 생성(모델의 탐욕 결과 기준), `within_game.py --game_meta`가 새 메타를 읽는지 확인.
- 분석 코드가 hidden 차원(Qwen3-4B 2560, Llama 3072)과 layer 인덱스(2 = 75%)를 그대로 처리하는지 합성 점검.

## 범위 밖 (한계로 기록)

- 7B 이상, 다른 환경은 하지 않는다(2026-10-17 사용자 결정).
