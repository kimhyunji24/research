# 같은 게임 다중 rollout(샘플링) 계획 (2026-10-15, 데이터를 만들기 전에 기록)

## 왜 하는가
`main_3b`의 정책은 탐욕적이라 같은 게임을 다시 돌리면 결과가 같다. 즉 episode의 라벨은 "게임 인스턴스"의 함수이고,
프로브가 실패를 잘 맞혀도 (1) 게임이 원래 어렵다는 것(과제 문장·방 묘사에서 오는 정보)을 읽은 것인지
(2) 진행 과정의 실패를 읽은 것인지 구분할 수 없다. baseline 5단(텍스트)이 step 0에서 이미 0.70인 것이 그 증상이다.
같은 게임을 샘플링으로 여러 번 돌리면, 같은 입력(게임)에서 성공과 실패가 갈리는 rollout이 생기고,
게임 단위 정보로는 설명되지 않는 신호만 평가할 수 있다.

## 설계
- 정책: `configs/main_3b.yaml`과 같은 프롬프트·후보 점수화. 선택만 탐욕 대신 `softmax(후보 로그확률 합 / T)`에서 샘플링한다.
  `T = 1.0`(모델 분포를 admissible 후보로 재정규화, 사용자 확인 2026-10-15). 난수는 (sample_seed, episode, step)으로 결정되어 재현 가능하고 resume에서도 같다.
- 게임: `collect/make_game_list.py`로 기존 250 episode의 게임 중에서 고른다. 각 게임을 `repeats`번 돌린다(환경이 순서를 섞으며 각 게임이 정확히 repeats번 나옴을 확인).
- 라운드: 같은 게임의 모든 rollout은 step 0의 프롬프트가 같다(hidden도 같음). 따라서 **step 0은 평가에서 제외**하고 step 1, 2, 3(두 번째~네 번째 action)을 본다.

## 단계
1. 파일럿: 20게임 x 8회 = 160 episode(약 25~35분). 목적은 성공률과 "성공과 실패가 갈리는 게임의 비율"을 보는 것이다. 프로브는 돌리지 않는다.
2. 파일럿 판정(임의 기준, 근거 없음): 8회 중 성공과 실패가 모두 나온 게임이 20개 중 6개(30%) 이상이면 본 규모로 간다.
   그렇지 않으면 `T`나 게임 선정을 바꿀지 사용자가 결정한다.
3. 본 규모: 100게임 x 8회 = 800 episode(약 2.4시간). 게임 선정과 `repeats`는 파일럿 결과 후 확정해 이 문서에 기록한다.

## 주 분석 (본 규모에서, 데이터를 보기 전에 고정)
- 대상: 성공과 실패가 모두 나온 게임들의 rollout 행(step 1, 2, 3에 살아 있는 episode).
- 지표: **게임 내 쌍 AUROC**. 같은 게임 안의 (실패, 성공) rollout 쌍에서 실패의 점수가 더 높은 비율. 게임별 쌍 수로 가중 평균.
- CI: 게임 단위 cluster bootstrap 1,000회. 프로브와 baseline의 차이는 같은 재표집으로 짝지음.
- 프로브: 3B reader, 75% layer, linear(nested C). 이 선택은 탐색 결과를 본 뒤에 고른 것이다(한계로 명시).
- baseline: 4단(진행도), 5단(텍스트). 같은 게임에서 같은 과제 문장이므로 step 1 이후의 차이는 history(샘플링된 action과 관찰)에서 온다.
- 교차적합: 한 게임의 모든 rollout은 같은 fold(장면 단위 그룹).
- 판정은 사전 등록한 비열등/우수 규칙(마진 0.05)을 그대로 적용한다.

## 해석 규칙 (결과 보기 전)
| 결과 | 해석 |
|---|---|
| 프로브 > baseline 4, 5 (CI 하한 > 0) | hidden state에 진행 과정의 실패 신호가 있다(난이도 텍스트로 설명되지 않음) |
| 프로브 ≈ baseline | 신호는 있으나 history에서 읽히는 정보 이상은 아니다 |
| 모두 0.5 근처 | 같은 게임 내 성공/실패는 이 방법으로 예측되지 않는다(샘플링 노이즈가 우세) |

## 한계 (미리)
- 정책이 탐욕에서 샘플링으로 바뀌어 `main_3b`의 결과와 직접 비교할 수 없다. 성공률이 달라질 수 있다.
- 갈리는 게임만 평가에 쓰이므로 선택 효과가 있다(어려운 게임만, 또는 중간 난이도 게임만 남음).
- `repeats=8`에서 같은 게임 내 rollout은 서로 독립이 아니다(앞부분이 같은 경로로 시작할 수 있음).
- 7B 4-bit, 0.5B/1.5B reader 확장은 본 분석 이후로 미룬다.

- 주 분석(게임 내 쌍 AUROC, step 1~3, 3B reader 75% layer linear vs baseline 4·5단)은 바꾸지 않는다. 위 장치는 보조 지표다.

## 보조 분석과 해석 규칙 (2026-10-17, 주 분석 결과를 열기 전에 기록)
주 분석 실행 시작 뒤, 결과 파일을 열기 전에 판정 규칙의 전제를 점검했다. 점검에는 점수·AUROC를 쓰지 않았고 라벨은 평가 쌍을 고르는 데만 썼다.
주 분석과 그 판정은 바꾸지 않고 그대로 보고한다. 아래는 그 판정이 무엇을 뜻하는지 정하기 위한 보조 분석과 해석 규칙이다.

### 점검 결과 (결과 열람 전)
| 항목 | 값 |
|---|---|
| 갈리는 게임 / 장면 | 39 / 28 (전체 100게임, 64장면). step마다 (실패, 성공) 평가 쌍 470개 |
| 프롬프트가 같은 평가 쌍 | step 1/2/3: 331 (70.4%) / 312 (66.4%) / 246 (52.3%) |
| 그 쌍의 프로브 입력(hidden layer 2) | 889쌍 모두 정확히 같다 -> 프로브 점수 동점(쌍 AUROC 기여 0.5) |
| 그 쌍의 baseline 4·5단 특징 | 889쌍 모두 `repeat` 또는 `p_chosen`이 다르다(현재 step에서 샘플링된 action의 값) |
| 생존 | 성공 episode 최소 4 step -> step 1~3에서 전원 생존 |
| 합친 `hidden.npy` | shard 640개를 이어붙인 것과 비트 단위로 같다 |

### 이 점검이 판정 규칙에 주는 문제
1. **동점 희석**: 프로브의 쌍 AUROC 상한은 0.5 x 동점 비율 + (1 - 동점 비율) = step 1/2/3에서 0.648 / 0.668 / 0.739다.
   마진 0.05는 갈라진 쌍 기준으로 0.169 / 0.149 / 0.105에 해당해 비열등 판정이 느슨하다. "모두 0.5 근처"는 "아직 갈라지지 않음"일 수 있다.
2. **시점 비대칭**: baseline 3단 이상의 `repeat`(현재 action 포함), `p_chosen`은 프로브 시점(프롬프트 마지막 토큰) 이후 값이다.
   게임 간 평가에서는 프로브에 불리한 보수적 선택이었지만, 게임 내 평가에서는 rollout이 갈라지는 지점이 바로 이 샘플링된 action이다.
   baseline이 이기면 이 정보 때문일 수 있다. (`n_cand`는 프롬프트의 admissible 목록에서 정해지므로 시점 문제가 없다.)
3. **정의 부족**: "≈"(비열등과 동등의 구분), "0.5 근처"의 수치 기준, 비교 6개(baseline 4·5단 x step 3개)의 다중 비교 규칙이 없었다.
4. **마진 근거**: 0.05는 게임 간 탐색 결과를 본 뒤 정한 값이고 게임 내 지표와 척도가 다르다.

### 보조 분석 (주 분석과 같은 교차적합 절차, seed 0, 게임 bootstrap 1,000회, 게임 내 순열 1,000회)
- **보조 1 (동점 제외)**: step s의 평가 쌍 중 두 rollout의 step s 프롬프트가 다른 쌍만으로 쌍 가중 AUROC(프로브, baseline 4·5단)와
  프로브 - baseline 차이의 CI를 낸다. 점수는 주 분석과 같은 교차적합 점수를 쓴다. step별 동점 비율을 함께 보고한다.
- **보조 2 (시점 맞춘 baseline)**: baseline 4t·5t = 4·5단에서 현재 step의 `repeat`, `p_chosen`을 직전 step의 값으로 바꾼 것
  (`n_cand`는 그대로). 같은 교차적합으로 다시 학습해 전체 쌍과 동점 제외 쌍에서 프로브와 비교한다.

### 해석 규칙 (주 분석과 보조 분석에 함께 적용)
- **우수**: 프로브 - baseline 차이의 95% CI 하한 > 0. 6개 비교(baseline 4·5단 x step 3개)에 Holm 보정을 하고,
  p는 게임 bootstrap 분포의 양측 p(2 x min(P(d<=0), P(d>=0)))를 쓴다. "baseline보다 낫다"는 4단과 5단을 모두 이길 때만 쓴다.
- **동등(≈)**: 차이의 95% CI가 (-0.05, +0.05) 안에 모두 들어갈 때만 쓴다. 하한만 -0.05를 넘는 것은 "비열등(약함)"으로 따로 적는다.
- **0.5 근처(예측 안 됨)**: 쌍 AUROC의 CI가 0.5를 포함하고 게임 내 순열 p > 0.05. 주 분석에서 이 판정이 나오면
  "갈라지지 않은 쌍이 많아서"와 구분하기 위해 보조 1을 함께 본다.
- 마진 0.05는 사후에 정했고 척도가 다르다는 한계를 결과 표 옆에 적는다. 게임 39개 수준의 cluster percentile bootstrap은 CI가 좁게 나올 수 있다(확인 필요).
- 보조 분석은 주 결과를 대체하지 않는다. 논문에는 주 결과(사전 등록)를 먼저, 보조 결과를 그 다음에 쓴다.

### 독립 복제 결정 (2026-10-17, 주 분석 결과를 열기 전)
- 게임 내 평가의 독립 복제(추가 게임 수집)는 **하지 않는다**(사용자 결정). 게임 내 결과는 파일럿 160 + 본 규모 640 episode(갈리는 게임 39개)만으로 보고한다.
- 따라서 결과를 본 뒤 이 평가를 위해 표본을 늘리지 않는다(optional stopping 방지). 이후 추가 수집이 필요해지면 새 목적의 별도 실험으로 사전 등록하고 이 결과와 합치지 않는다.
- 결과 열람 전 노출: 다른 작업 세션이 진행 확인 중 `results/within_game.log` 앞 두 줄(실행 규모와 eta² 점추정)을 본 적이 있다. 그 밖의 결과는 이 결정 전에 보지 않았다.
- 보조 분석 코드 `probes/within_game_supp.py`는 결과 열람 전에 작성했고, 합성 데이터 점검을 통과했다. 무작위 라벨 점검은 실행 중이다.
