# 선행 방법식 baseline 비교 계획 (2026-10-20, 결과 보기 전 기록, 탐색)

논문 4.5절용. 확증 근거로 쓰지 않는다. 1회 실행한다.

## 목적
선행연구가 비교한 "과제를 보지 못하는" 모니터를 우리 데이터에서 근사해, 같은 분할·같은 통계로 프로브와 baseline 사다리 옆에 놓는다.
토의에서 "과제를 보지 못하는 모니터와의 비교는 hidden state가 더하는 정보를 과대평가할 수 있다"고 시사한 부분을 직접 본다.

## 데이터·설정 (기존과 같음)
- Qwen2.5-3B, `data/main_3b` 앞 250게임(탐색 구간), 과제 단위, step 0·1·2(사전 등록 라운드와 같음).
- 장면 단위 층화 5-fold × 2(seed 0·1), nested C(10⁻⁴~1), 장면 cluster bootstrap 1,000회(seed 0), 순열 100회. `probes/lib.py`의 `round_eval`, `paired_diff`.
- 프로브: 3B 자기 hidden 75% 깊이(인덱스 2), linear. 참고로 5단도 같은 실행에서 다시 계산한다.

## 새 baseline (저장된 `steps.jsonl` 필드만 사용, 표준화 + L2 로지스틱)
| 이름 | 따라 한 선행연구 | 특징 |
|---|---|---|
| B-behav | Doomed from the Start [3]의 행동 scorer | 고른 action의 로그확률 합, 토큰 평균 로그확률, 토큰 수(각각 현재 step과 직전 step; step 0의 직전 값은 0), 프롬프트 토큰 수(prefix 길이), 현재 관찰의 오류 문구 수("nothing happens", "can't", "cannot") |
| B-logp | AgentStop [1]의 토큰 로그확률 특징 | 후보 점수 softmax의 엔트로피, 1·2위 점수 차, 고른 action 확률(p_chosen), 후보 수, 고른 action의 토큰 평균 로그확률(현재·직전 step) |
| B-behav+task | B-behav + 과제 유형 6개(사다리 2단 정보) | 과제 정보를 더하면 차이가 얼마나 줄어드는지 |

- 현재 step의 로그확률 특징은 행동을 점수화한 뒤의 값이라 프로브 입력보다 조금 늦다(사다리 3단과 같은 이유로 baseline에 유리한 쪽).
- 후보 점수화라 토큰별 로그확률은 저장되지 않았다. 최소 토큰 로그확률 등은 쓰지 못하고 합·평균만 쓴다.

## 비교 (탐색)
1. 프로브 − B-behav, 프로브 − B-logp (step 0·1·2)
2. B-behav+task − B-behav
3. 참고: 프로브 − 5단, B-behav − 5단
- 판정 표기는 기존 규칙(우수 = CI 하한 > 0, 열등 = 상한 < 0, 그 밖 결론 없음)을 쓰되 탐색으로만 보고한다. 다중 비교 보정은 하지 않고 비교 수를 함께 적는다.

## 미리 정한 해석
- 프로브가 B-behav·B-logp보다 우수하지만 5단보다 낫지 않으면: "약한 baseline 대비 이득은 과제 정보를 넣으면 사라진다"를 시사.
- 프로브가 B-behav보다도 우수하지 않으면: "이 설정에서는 약한 baseline 대비로도 hidden state 이득이 보이지 않는다"(선행연구와 다른 점, 환경·정책 차이 가능).
- 어느 경우든 "선행연구 재현"이라고 쓰지 않고 "선행연구식 특징을 우리 정책에 맞춰 근사한 것"으로 쓴다.

## 한계 (미리)
- 정책이 후보 점수화라 "생성 토큰 수"는 후보 토큰 수이고, 오류 문구는 거의 나오지 않는다('Nothing happens' 0회, `early_stop_plan` 변경 이력).
- 환경·모델·정책이 선행연구와 다르다. 텍스트 모니터(Fail-Fast식 소형 LM 미세조정)는 하지 않는다(GPU 필요, 텍스트 정보는 5단 TF-IDF가 담음).
- 앞 250게임은 이미 여러 탐색에 썼다.

## 출력
- 스크립트 `scripts/2026-10-20/prior_methods.py`, 결과 `results/prior_methods_3b.csv`, `_diff.csv`, `.log`.

## 변경 이력
- 2026-10-20: 최초 기록(실행 전, 사용자 확인).
- 2026-10-20 (실행 전 특징 점검, 라벨 미사용, `--check_only`): step 0–2의 750행에서 결측 0. 오류 문구 수는 모든 행에서 0이라 상수 특징이 된다(후보 점수화에서는 오류 응답이 없음). 특징 목록은 바꾸지 않는다.
  고른 action 토큰 수는 `Action: … <|im_end|>`를 포함해 7–17이다.
