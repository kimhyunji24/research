# 3차 리뷰 B: 기존 데이터 추가 분석 계획 (2026-10-21, 실행 전 고정)

3차 리뷰(박사급 리뷰어 관점)가 요청한 추가 분석 중 **새 수집 없이 기존 데이터로 할 수 있는 것**만 한다. 모두 **탐색**이며 사전 등록·확증 판정을 바꾸지 않는다.
이 문서는 결과를 보기 전에 commit하고, 각 분석은 1회만 실행한다. 바꾸면 맨 아래 변경 이력에 날짜와 이유를 적는다.

## 공통
- 데이터: `data/main_3b/Qwen2.5-3B-Instruct`의 **앞 250개 episode, step 0–2**(사전 등록 라운드, 모든 episode 진행 중). 행 750개, 실패 194/250.
- 쓰지 않는 데이터: 확증 홀드아웃(episode 250–499), Qwen3-4B, ReAct, 게임 내(시도 수준) 데이터. 사전 기록 분석을 다시 돌리거나 확증 데이터를 다시 분석하지 않기 위해서다.
- 교차적합: 기존과 같이 장면 단위 `StratifiedGroupKFold` 5-fold × 반복 2(seed 0, 1), 선형 모델 C는 바깥 학습 fold 안 3-fold nested(`C_GRID` = 1e-4–1), 점수는 반복 평균.
- 신뢰구간: 장면 단위 cluster bootstrap 1,000회(seed 0, `lib.cluster_boot_idx`), 방법 간 차이는 같은 재표집에서 짝지어 계산. step 0–2의 행은 같은 250개 episode라 같은 장면 재표집을 세 step에 함께 써서 **step 평균** 차이와 CI도 낸다.
- 비교 대상 기호: P75 = 3B 프로브 75% 깊이(layer 27) 선형, P50 = 50% 깊이(layer 18, 사전 등록 깊이) 선형, R4·R5 = baseline 4·5단(기존 정의 그대로).
- 출력: `results/review_b_*.csv`(새 이름). 출력 파일이 있으면 멈춘다. 로그에 시작·종료 시각과 HEAD를 남긴다. 실행 전 라벨을 섞은 smoke 점검으로 파이프라인을 확인한다(결과 아님).
- 보정: 분석마다 family를 두고 Holm 보정 p를 함께 적는다(게임 bootstrap 양측 p). 해석은 차이와 CI로 하며 "우수/열등"은 CI 기준의 기술적 표현이다.

## B1. 학습 표본 수에 따른 learning curve (리뷰 11-1, 질문 2)
- 바깥 학습 fold(약 200 episode)에서 행을 비율 f ∈ {0.25, 0.5, 0.75, 1.0}만 뽑아 학습하고(라벨 층화, f < 1은 뽑기 5회 seed 0–4, f = 1은 1회), 시험 fold 전체에 점수를 매긴다. nested C는 뽑은 학습 행 안에서 고른다.
- 방법: P75, P50, R4, R5. 지표: step별·step 평균 AUROC와 CI, P75 − R5와 P50 − R5 차이와 CI.
- f = 1.0의 P75는 기존 값(0.666, 0.721, 0.795; `results/probe_strength_3b.csv` base)을 재현해야 한다(재현 점검).
- 해석 규칙: f가 커질수록 P75 − R5가 줄어드는지 기술한다. 줄어들면 "프로브가 데이터에 제한되었을 수 있다"고만 쓰고, 약 200 episode를 넘는 외삽은 하지 않는다.
- 3,553게임 전체로의 확대는 하지 않는다(표본 확대 금지 규칙, 새 수집).

## B2. 낮은 오탐 구간 지표 (리뷰 4절)
- B1의 f = 1.0 점수를 쓴다. 양성은 실패, 오탐은 성공을 실패로 표시한 것(멈추면 잃는 성공).
- 지표: 오탐률 5%·10%에서의 검출률(ROC 곡선에서 FPR ≤ 기준인 점 중 최대 TPR), 부분 AUROC(FPR ≤ 0.10, McClish 표준화, `roc_auc_score(max_fpr=0.1)`), AUPRC.
- 방법: P75, P50, R4, R5. 차이: P75 − R5, P50 − R5(짝지은 bootstrap).
- 주의(미리): 성공이 56개라 오탐률 5%는 성공 약 3개에 해당하며 매우 불안정하다.
- 해석 규칙: P75 − R5의 CI가 0을 벗어나면 "배포에 중요한 구간에서는 AUROC와 다른 그림"으로 보고한다. 아니면 AUROC 결론과 같은 방향으로 기술한다.

## B3. 절감률 대 성공 손실 곡선 (리뷰 5절)
- 새 계산 없음. `results/early_stop_3b_curves.csv`(방법별 문턱마다 절감률·손실)와 `results/early_stop_3b_fold.csv`(다른 fold에서 고른 문턱)를 그림으로 그린다.
- 방법: step 상한, 루프 감지, 4t, 5t, 프로브. 손실 0–100% 전체와 0–10% 확대. 그림 스크립트는 `scripts/2026-10-21/` 아래, 그림은 `figures/`에 새 이름.

## B4. 실제 예측 방법으로 잰 게임 단위 대 장면 단위 분할 (리뷰 4절 마지막)
- P75와 R5를 장면 단위 대신 게임 단위 그룹(`task_id`)으로 같은 절차로 교차적합한다. 탐욕 데이터는 게임당 episode가 1개라 게임 단위 분할은 episode 단위 분할과 같다.
- 지표: 두 분할의 AUROC, 차이(게임 단위 − 장면 단위)와 장면 bootstrap CI, step별·step 평균.
- 해석 규칙: 차이가 크면 "실제 방법에서도 부풀림이 있다", 작으면 "합성 특징만큼의 부풀림은 실제 방법에서 보이지 않았다"로 보고한다.

## B5. 과제 수준 신뢰구간 포함률 (리뷰 4절)
- 라벨을 step마다 섞은 데이터(seed 1001–1020, 20회)에서 P75와 R5를 기존 절차로 교차적합하고, 장면 bootstrap(1,000회) 95% percentile 구간이 AUROC 0.5와 차이 0을 포함하는 비율을 센다.
- 지표: 포함률(20 seed × 3 step = 60회)과 Wilson 95% CI, 방법별·차이별.
- 해석 규칙: 포함률이 90% 미만이면 과제 수준 구간도 명목보다 좁다는 단서를 논문에 단다.

## B6. 생성 action 토큰 위치 프로브 (리뷰 3절, 11-2) — GPU, 사용자가 있을 때만
- 3B actor에 저장된 프롬프트 + 실제로 고른 후보의 점수화 이어붙임 `Action: <action><|im_end|>`를 teacher forcing으로 넣고, **action 텍스트의 마지막 토큰**(`<|im_end|>` 직전)의 hidden을 50%·75% 깊이(layer 18, 27)에서 뽑는다([3]이 읽는 위치에 해당).
- 점검: 프롬프트 부분 토큰 수가 `prompt_tokens`와 같은지, 프롬프트 마지막 토큰 hidden이 저장된 hidden과 같은지(앞 5 step), action 토큰 열이 비어 있지 않은지.
- 저장: `data/main_3b/action_token/Qwen2.5-3B-Instruct/hidden.npy`(새 폴더, 앞 250 episode의 step 0–2 행만, 순서는 hid_idx).
- 비교: action 토큰 프로브(A50, A75) − R5, A75 − P75. 주의: action 토큰은 행동을 고른 뒤의 상태라 프롬프트 프로브보다 늦은 정보를 담는다(R3–R5의 현재 step 특징과 같은 시점).
- 해석 규칙: A75 − R5의 CI 하한이 0보다 크면 "프로브 위치가 결론을 바꿀 수 있다"고 보고하고 [3]과의 대비 문장을 고친다. 아니면 위치를 바꿔도 같은 결론으로 기술한다.

## B7. 신경망 텍스트 인코더 baseline (리뷰 3절, 11-5)
- 인코더: `BAAI/bge-base-en-v1.5`(revision은 내려받을 때 고정해 이 문서 변경 이력에 적음), 기존 `.venv`의 transformers로 실행(새 패키지 설치 없음).
- 입력: 5단과 같은 `text` 열(user 메시지 전체). 510 토큰 단위로 나눠 각 조각의 CLS 임베딩을 L2 정규화하고 평균한 뒤 다시 정규화한다(잘림 없음).
- 방법: E = 임베딩만(표준화 + 로지스틱, nested C), R5e = 4단 숫자 특징 + 임베딩(5단의 TF-IDF를 임베딩으로 바꾼 것).
- 비교: R5e − R5, P75 − R5e, P75 − E.
- 해석 규칙: R5e − R5의 CI가 0 위면 "더 강한 텍스트 baseline이 있다"로 보고하고 프로브와의 비교를 R5e 기준으로도 적는다.

## 하지 않는 것과 이유
- 18개 비교를 합친 효과 추정치: 비교들이 게임·baseline을 공유해 요약 통계로 합치면 구간이 너무 좁아지고, 개별 자료로 합치려면 사전 기록 분석(확증, Qwen3-4B, ReAct)을 다시 돌려야 한다. 대신 B1에서 step 평균 차이를 낸다.
- 리뷰의 C(3,553게임 확대, 같은 prefix에서 분기한 continuation의 성공률, 다른 환경, 7B 이상 actor): 새 수집이고 표본 확대 금지 규칙과 부딪혀 이 계획에 넣지 않는다.

## 실행 순서
1. 이 문서 commit. 2. 스크립트 작성과 smoke 점검(라벨 섞음, 결과 아님). 3. B3(그림), B1·B2, B4, B5, B7(CPU) 1회 실행. 4. 사용자 있을 때 B6(GPU) 추출과 분석 1회 실행. 5. 결과 절과 논문 탐색 절(전체판 4.8, 축약판 한 단락) 추가.

## 결과 (2026-10-21 실행, 모두 탐색)
공통: step마다 250 episode(실패 194, 성공 56), 괄호는 장면 cluster bootstrap 1,000회 95% CI. "step 평균"은 step 0–2 평균. Holm 보정은 분석(B1, B2, B4, B7, B6)별 family 안에서. 재현 점검: f = 1.0의 P75 0.666/0.721/0.795, P50 0.520/0.599/0.665, R4 0.673/0.700/0.834, R5 0.701/0.732/0.823이 기존 `results/probe_strength_3b.csv`·`results/probe_main_3b_primary.csv`와 같음. 해석은 모두 "시사한다" 수준이며 사전 등록·확증 판정을 바꾸지 않는다.

- 덧붙임(시사): step 1에서 A75가 P75보다 높았고(Holm p = 0.048), 50% 깊이는 action 토큰에서 0.746으로 프롬프트 위치(P50 0.594)보다 높았다. 50% 깊이의 약함은 읽는 위치에 따른 것일 수 있다. action 토큰은 행동을 고른 뒤의 상태라 프롬프트 프로브보다 늦은 정보를 담는다.

### B7 신경망 텍스트 인코더 (`results/review_b_textenc.csv`, `_textenc_diff.csv`, step 평균)
| 비교 | 값 |
|---|---|
| E(bge 임베딩만) AUROC | 0.594 (0.518–0.666) |
| R5e(4단 숫자 + 임베딩) AUROC | 0.637 (0.556–0.710) |
| R5e − R5 | −0.115 (−0.187, −0.052) |
| P75 − R5e | 0.090 (0.039, 0.142) |
| P75 − E | 0.133 (0.074, 0.187) |
- 해석 규칙 적용: R5e − R5가 0 위가 아니므로 "더 강한 텍스트 baseline"은 찾지 못했다. 이 설정의 bge 임베딩은 TF-IDF보다 약했고, R5e가 4단 숫자 특징만 쓴 R4(0.736)보다도 낮아 고차원 임베딩이 학습을 방해했을 수 있다(확인 필요). 따라서 P75가 R5e·E보다 높다는 결과는 "프로브가 신경망 텍스트 baseline을 넘는다"는 근거가 아니다. 공통 지시문·후보 목록이 긴 프롬프트의 CLS 평균이 상태 차이를 흐렸을 가능성도 있으나 시험하지 않았다.

### 요약
- 기존 결론(75% 깊이 프로브가 5단 baseline을 넘지 못함)은 학습 표본 수(B1), 낮은 오탐 구간 지표(B2), 분할 단위(B4), 읽는 위치(B6)를 바꿔도 같은 방향이었다.
- 새로 붙일 단서: 과제 수준 구간의 포함률이 명목보다 낮을 수 있음(B5), 시험한 신경망 인코더는 TF-IDF보다 약해 더 강한 텍스트 baseline 문제는 열려 있음(B7).
